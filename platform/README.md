# Платформа курсу

Локальний сайт, який читає уроки з `content/`, показує їх у три колонки і перевіряє завдання в браузері
через Pyodide (CPython у WebAssembly) у Web Worker. Без бекенду, без npm, прогрес у `localStorage`.

## Запуск

З кореня курсу:

```bash
.venv/bin/python platform/fetch_vendor.py   # один раз: Pyodide, marked, highlight.js, Ace, шрифти -> platform/vendor/
.venv/bin/python platform/serve.py          # збирає курс і відкриває http://localhost:8765/
```

Або через конфігурацію `platform` у `.claude/launch.json`. Параметри сервера: `--port 8765 --host 127.0.0.1`.
Можна і без `serve.py`: `.venv/bin/python platform/build.py && .venv/bin/python -m http.server 8765 --directory platform`.

`serve.py` перед кожною віддачею `dist/course.json` перевіряє, чи змінилось щось у `content/`, і перезбирає курс:
після правки уроку достатньо перезавантажити сторінку. Якщо збірка падає, сторінка показує текст помилки.

## Збірка (`build.py`)

`build.py` читає `content/course.yaml` (порядок модулів і уроків), для кожного уроку `lesson.md` (YAML-frontmatter +
Markdown) і `tasks.yaml`, і пише один файл `platform/dist/course.json`. Markdown не рендериться, лише пакується;
рендер робить браузер (marked + highlight.js).

У `course.yaml` урок задається рядком-slug (папка `content/<module>/<slug>/`) або словником `{slug, title}` для
ще не написаних уроків: якщо папки немає, сайдбар показує урок сірим як "ще не написано". Id уроку береться з
frontmatter і має збігатися з `m<N>-l<NN>` з назв папок.

Збірка зупиняється зі списком усіх проблем, якщо:
- `tasks.yaml` не парситься або не є списком; у завдання немає обов'язкових полів; `answer` у quiz поза межами;
- `<!-- task: id -->` (поза кодовими блоками) посилається на неіснуючий id;
- завдання з `tasks.yaml` не вставлене в урок або вставлене двічі;
- `requires` браузерного завдання містить щось, крім `pydantic` і `httpx`.

## Як платформа рендерить урок

- `<!-- task: id -->` на окремому рядку стає віджетом завдання (`code`, `quiz`, `project`).
- ```` ```python live ```` стає редактором із кнопками "Запустити"/"Скинути"; наступний за ним ```` ```text ```` показується
  як "Очікуваний вивід" поруч із фактичним.
- Пара ```` ```ts ```` + ```` ```python ```` поспіль показується у два стовпці на ширині від 900px.
- Blockquote з `**JS-аналог.**`, `**Пастка.**`, `**Під капотом.**`, `**Для капстоуну.**` стає callout з власним кольором і міткою.
- Заголовки `##` отримують `id` і потрапляють у праву колонку "На цій сторінці" (scroll-spy, статус завдань розділу).
- URL `#m1-l06` відкриває урок, `#m1-l06/t3` ще й скролить до завдання.

## Виконання Python

- `worker.js` завантажує Pyodide ліниво при першому запуску; `runner.js` на головному потоці ставить запуски в чергу,
  тримає таймаут 15 секунд і на "Зупинити" вбиває воркер і одразу створює новий.
- Код учня компілюється як файл `main.py` у свіжому модулі `__main__` (новий простір імен на кожен запуск),
  нічого не дописується перед першим рядком, тож `from __future__ import annotations` працює.
  Після запуску прибираються модулі, які створив код учня (наприклад, пакети в `tempfile`), і відновлюються `sys.path` та cwd.
- stdout і stderr ідуть окремими потоками; traceback очищений від внутрішніх кадрів Pyodide, шляхи скорочені до імені файлу.
- `asyncio.run(<expr>)` поза функціями (і на верхньому рівні, і в `if __name__ == "__main__":`) замінюється на
  `await <expr>` через обгортку, яка, як і справжній `asyncio.run`, скасовує задачі, що лишились після `main()`.
  `asyncio.run` усередині функції не чіпається.
- Пакети: `pydantic` (і залежності), `sqlite3`, `lzma` вендорені; потрібний пакет завантажується автоматично за
  `import` у коді або за `requires` завдання.
- "Перевірити" = код учня + `\n\n` + `harness` (+ `\n\n` + `asserts`). Порівняння з `expected` ігнорує кінцеві
  пробіли в рядках і порожні рядки в кінці. Для `asserts` повідомлення `AssertionError` показується учню.

## Прогрес

`localStorage["pycourse.v1"]`: `{passed, drafts, checklists, current, collapsed}`. Кнопки "Експорт"/"Імпорт" у шапці
зберігають і відновлюють його як `pycourse-progress.json` (імпорт питає підтвердження).

Тема: кнопка "Тема" у шапці перемикає система → світла → темна; вибір лежить окремо в `localStorage["pycourse.theme"]`
і ставить `data-theme` на `<html>`. У режимі "система" атрибута немає і працює `prefers-color-scheme`.

## Оновлення вендору

Версії закріплені на початку `fetch_vendor.py`:

| Бібліотека | Версія | Звідки |
|---|---|---|
| Pyodide | 0.29.5 (Python 3.13.2, pydantic 2.12.5) | cdn.jsdelivr.net/pyodide |
| marked | 18.0.14 | jsdelivr npm |
| highlight.js | 11.12.0 (`@highlightjs/cdn-assets`) | jsdelivr npm |
| Ace | 1.44.0 (`ace-builds`) | jsdelivr npm |
| IBM Plex Sans/Mono | fontsource 5.3.0 | jsdelivr npm |

Щоб оновити: змінити номер версії, запустити `.venv/bin/python platform/fetch_vendor.py --force`, потім відкрити
`http://localhost:8765/selftest.html` і переконатись, що всі рішення проходять. Будь-яку збірку Pyodide можна
спробувати без вендорингу: `selftest.html?pyodide=https://cdn.jsdelivr.net/pyodide/v<версія>/full/`.

Чому 0.29.5, а не найновіша 314.x: лінія 314 це Python 3.14 і завантажується як ES-модуль (`pyodide.asm.mjs`),
а курс пишеться під 3.12. Лінія 0.27 (Python 3.12) має pydantic 2.10, де ще немає `validate_by_name`, і завдання
m2-l09/t4 на ній не проходить. 0.29.5 (Python 3.13) проходить усі 127 завдань з кодом.

## Самоперевірка

`http://localhost:8765/selftest.html` проганяє через той самий воркер:
- рішення кожного браузерного завдання з кодом (мають пройти всі);
- стартовий код кожного завдання (не має проходити);
- кожен живий приклад, за яким іде блок ```` ```text ````, з порівнянням виводу (інформаційно: частина очікуваних
  виводів у уроках містить traceback локального файлу, `$ python ...` чи версію Python і збігатися не може).

Параметри: `?only=m2-l09`, `?live=0`, `?starter=0`, `?pyodide=<base url>`.

## Відомі обмеження

- Різниця версій: у браузері Python 3.13 і pydantic 2.12, локально 3.12 і pydantic 2.14. Текст помилок і
  посилання `errors.pydantic.dev/2.x` у виводі можуть відрізнятися від показаних в уроці.
- Таймери в браузері менш точні, ніж у CPython: asyncio-приклади з різницею тривалостей у кілька мілісекунд
  (m5-l05, живий приклад із Semaphore) зрідка дають інший порядок рядків.
- `asyncio.run` усередині функції в Pyodide падає з "cannot be called from a running event loop".
- Після заміни `asyncio.run` позначки `^^^` у traceback для цього рядка можуть бути зсунуті на кілька символів.
- `input()` одразу отримує EOF (`EOFError`).
- Живі приклади не зберігають правки між перезавантаженнями (чернетки зберігаються лише для завдань).
