# Ключові питання уроку m4-l02 "dunder-методи: __repr__, __eq__, __hash__, __iter__, __call__"

Урок готовий, коли на кожне питання є відповідь з кодом і виводом.

- [x] Що таке dunder (double underscore) методи і "протокол через імена": оператор чи вбудована функція шукає метод на класі, а не на екземплярі. Чому `len(x)` замість `x.length` і чим це відрізняється від `Symbol.iterator`/`toString`/`valueOf`.
- [x] `__repr__` проти `__str__`: для кого кожен, що показує REPL, f-рядок `{x!r}`, чому `__repr__` обов'язковий, а `__str__` за потреби; формат "як створити об'єкт".
- [x] `__eq__` і `__hash__`: визначення `__eq__` робить клас unhashable, якщо не визначити `__hash__`; контракт "рівні об'єкти мають однаковий хеш"; `NotImplemented` для чужих типів; `__ne__` виводиться автоматично. Чому змінюваний об'єкт не має бути hashable.
- [x] Порівняння: `__lt__` та інші, `functools.total_ordering`, сортування об'єктів без `key`.
- [x] Контейнерні: `__len__`, `__getitem__` (з int і slice), `__setitem__`, `__contains__`, `__iter__` (повертає ітератор; генератор як найпростіший спосіб, посилання на m5-l02), `__bool__` і його зв'язок з `__len__` (посилання на m1-l03). Чому `__getitem__` з 0..n уже робить об'єкт ітерованим (старий протокол, одне речення).
- [x] Арифметика і оператори: `__add__`, `__radd__` (чому потрібен для `sum` і `0 + obj`), `__iadd__`, `__neg__`, `__matmul__` одним реченням. Контракт повертати новий об'єкт для незмінних типів.
- [x] `__call__`: об'єкт як функція, для чого (конфігуровані рендерери, декоратори-класи, посилання на m5-l04). Аналог: у JS об'єкт не може бути викликаним без Proxy.
- [x] `__getattr__` проти `__getattribute__`, `__setattr__`, `__delattr__`: проксі-об'єкти, пастка рекурсії в `__setattr__`. Одне речення про дескриптори з посиланням на m4-l03.
- [x] `__enter__`/`__exit__` одним реченням з посиланням на m4-l07; `__init_subclass__` і `__class_getitem__` одним реченням.
- [x] Для капстоуну: клас `ElementTree` з `__len__`, `__iter__` (обхід у глибину), `__getitem__` за `name`, `__contains__`, `__repr__`; порівняння двох конфігів через `__eq__`.
- [x] Які JS-звички тут шкодять: `toString` для всього, перевизначення `==` неможливе в JS (тут `__eq__`), `valueOf`, `Symbol.iterator` з `next()` на тому ж об'єкті (у Python `__iter__` і `__next__` зазвичай розділені), `length` як властивість.
