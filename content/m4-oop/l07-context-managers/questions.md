# Ключові питання уроку m4-l07 "Контекстні менеджери: with, contextmanager"

Урок готовий, коли на кожне питання є відповідь з кодом і виводом.

- [x] Проблема: ресурс треба звільнити навіть при винятку; `try/finally` і чому `with` кращий. `with open(...) as f`: що відбувається при вході, виході, винятку. Порівняти з `try/finally` у JS і `using` з TS 5.2 / explicit resource management.
- [x] Протокол: `__enter__` (повертає те, що йде в `as`), `__exit__(exc_type, exc, tb)` (повертає True, щоб проковтнути виняток, інакше виняток летить далі). Власний клас `Timer` або `ChangeDir`.
- [x] `contextlib.contextmanager`: генератор з одним `yield`, код до нього вхід, після виходу, `try/finally` навколо `yield` для гарантії очищення, `except` для обробки винятку з тіла. Чому це найчастіша форма в коді.
- [x] Кілька менеджерів в одному `with` (`with a() as x, b() as y:`), дужки в 3.10+, вкладені `with`, `contextlib.ExitStack` для динамічної кількості ресурсів.
- [x] Корисні готові: `contextlib.suppress(FileNotFoundError)`, `redirect_stdout`, `closing`, `nullcontext`, `tempfile.TemporaryDirectory`, `threading.Lock` як менеджер, `pytest.raises` як менеджер (посилання на m3-l03).
- [x] Повторне використання і реентерабельність: менеджер, який можна використати двічі, і який ні (генераторний одноразовий); менеджер як декоратор через `ContextDecorator`.
- [x] Асинхронні `async with` і `asynccontextmanager` одним прикладом з посиланням на m5-l06 і m7-l01 (lifespan).
- [x] Для капстоуну: `contextmanager` для тимчасової робочої директорії збірки (створити, віддати шлях, прибрати навіть при помилці), `Timer` для вимірювання етапів генерації, `ExitStack` для відкриття набору файлів шаблонів.
- [x] Які JS-звички тут шкодять: `try/finally` вручну всюди, `using` з `Symbol.dispose` як новинка (тут це 2006 рік), очікування, що `with` створює scope (не створює: змінна `f` живе після блоку).
