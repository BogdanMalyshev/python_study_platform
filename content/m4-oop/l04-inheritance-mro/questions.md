# Ключові питання уроку m4-l04 "Наслідування, super(), MRO, mixins"

Урок готовий, коли на кожне питання є відповідь з кодом і виводом.

- [x] Одинарне наслідування: `class B(A)`, перевизначення методів, `super().__init__(...)`, `isinstance`/`issubclass`, усе наслідує від `object`. Порівняти з `extends`/`super()` і чому `super()` у Python без аргументів усередині методу.
- [x] Множинне наслідування і MRO: C3-лінеаризація на прикладі ромба, `Class.__mro__`, чому `super()` означає "наступний у MRO", а не "батько", і як це дозволяє кооперативні `__init__` через `**kwargs`. `TypeError: Cannot create a consistent method resolution order`.
- [x] Mixins: невеликі класи з поведінкою без стану (`JsonMixin`, `ReprMixin`), порядок у списку батьків (mixins ліворуч), чому mixin без `__init__` простіший. Аналог: TS mixins через функції й чому в Python це вбудовано.
- [x] Перевизначення й розширення: виклик батьківського методу через `super()`, LSP одним реченням (підклас не ламає контракт), чому перевизначати `__init__` з іншою сигнатурою ризиковано.
- [x] Атрибути класу й наслідування: пошук по MRO, перевизначення константи в підкласі, `__init_subclass__` для реєстрації підкласів (реєстр рендерерів за `type` без ручного декоратора).
- [x] Наслідування від вбудованих типів (`class MyDict(dict)`) і його пастки (`__setitem__` не викликається з `update`); `collections.UserDict` і композиція як правильний шлях (посилання на m4-l08).
- [x] Коли наслідування доречне: справжнє "є різновидом" з потребою поліморфізму; коли ні: повторне використання коду (композиція), "зручно взяти методи" (mixins або функції). Правило: глибина ієрархії 1–2.
- [x] Абстрактні методи без ABC: `raise NotImplementedError` у базовому класі і чому ABC (m4-l05) кращий.
- [x] Для капстоуну: базовий `Renderer` з `render(element)` і підкласи `HtmlRenderer`, `TextRenderer`; `__init_subclass__` реєструє їх за ім'ям формату; mixin `TimingMixin`, що вимірює час рендеру через `super()`.
- [x] Які JS-звички тут шкодять: `super()` обов'язково першим рядком (у Python ні), прототипний ланцюжок замість MRO, `instanceof` з класами з різних модулів (тут те саме, але ідентичність класу), `Object.assign(Base.prototype, mixin)`, очікування, що множинного наслідування немає.
