# Ключові питання уроку m4-l08 "Композиція замість наслідування, патерни в ідіоматичному Python"

Урок готовий, коли на кожне питання є відповідь з кодом і виводом. Учень знає GoF-патерни з JS/TS; урок показує, як вони виглядають у Python і які з них зникають.

- [x] Композиція проти наслідування: об'єкт тримає інший об'єкт і делегує; коли кожне доречне; делегування через явні методи, через `__getattr__`, через Protocol для типу залежності. Приклад: `Worker` має `Renderer` і `Publisher`, не наслідує їх.
- [x] Інʼєкція залежностей без фреймворку: залежності як параметри `__init__` з типом Protocol, значення за замовчуванням для продакшн-реалізації, fake у тестах (посилання на m3-l04). Чому DI-контейнер у Python рідко потрібен.
- [x] Патерни, які стають функціями: Strategy (функція або `Callable` у параметрі), Command (функція + `partial`), Observer (список callback-ів), Template Method (функція з hook-параметрами або ABC з m4-l05). Показати кожен "до" (клас) і "після" (функція).
- [x] Патерни, які стають мовними конструкціями: Singleton (модуль або `functools.cache` на фабриці), Iterator (`__iter__`/генератор), Decorator (декоратор, m5-l04), Context Manager як Resource Acquisition, Factory (classmethod `from_dict` або `type` як фабрика), Builder (keyword-аргументи і dataclass з defaults).
- [x] Патерни, які лишаються класами: Adapter (обгортка над чужим API), Facade, State (Enum + словник переходів або класи станів), Registry (словник ім'я → клас, заповнений `__init_subclass__` або декоратором).
- [x] Duck typing як заміна багатьом інтерфейсним патернам: функція приймає "щось із `render`", і адаптер часто не потрібен.
- [x] Mixin проти композиції: коли mixin (поведінка без стану, що потребує `self`), коли композиція (стан, тестованість, заміна в рантаймі).
- [x] Плоска структура замість глибокої ієрархії: правило "один рівень наслідування, далі композиція"; як рефакторити ієрархію рендерерів з m4-l04 у композицію `Renderer(tag_strategy, escaper)`.
- [x] Для капстоуну: архітектура пайплайну генерації з композиції: `Pipeline(validator, renderer, publisher, clock)`, кожен залежить від Protocol, реєстр рендерерів, Observer для статусів (список callback-ів, прообраз WebSocket-сповіщень у m7-l04).
- [x] Які JS-звички тут шкодять: класи для всього (сервіси без стану), DI-контейнер як у NestJS/Angular, Singleton через модульний патерн із замиканням (тут просто модуль), інтерфейс + клас-реалізація + фабрика для кожної дрібниці, `abstract class` для стратегії.
