# Ключові питання уроку m4-l05 "ABC проти Protocol"

Урок готовий, коли на кожне питання є відповідь з кодом і виводом. m2-l07 уже дав Protocol; тут ABC глибоко і правило вибору.

- [x] `abc.ABC` і `@abstractmethod`: клас з абстрактним методом не інстанціюється (`TypeError: Can't instantiate abstract class`), підклас мусить реалізувати всі; абстрактні `property`, `classmethod`, `staticmethod`. Чому перевірка відбувається при створенні екземпляра, а не при визначенні класу.
- [x] Абстрактний метод із реалізацією за замовчуванням (template method): базовий `render` викликає абстрактні `open_tag`/`close_tag`.
- [x] `ABC.register` для віртуальних підкласів і `__subclasshook__`: як `collections.abc.Sized` розпізнає будь-який клас з `__len__`; чому це середина між номінальною і структурною типізацією.
- [x] `collections.abc`: `Iterable`, `Iterator`, `Sequence`, `MutableSequence`, `Mapping`, `MutableMapping`, `Set`: які методи треба реалізувати, а які дістаються безкоштовно (mixin-методи), на прикладі власної `Mapping`-колекції елементів форми з `__getitem__`, `__iter__`, `__len__`, що автоматично отримує `get`, `items`, `keys`, `__contains__`.
- [x] Правило вибору: ABC, коли ви володієте ієрархією і хочете спільний код та перевірку в рантаймі; Protocol, коли приймаєте чужі об'єкти або типізуєте параметр функції (посилання на m2-l07). Таблиця: перевірка (рантайм/статична), наслідування (потрібне/ні), спільний код (так/ні), `isinstance` (так/лише runtime_checkable).
- [x] Комбінація: Protocol для типу параметра плюс ABC як зручна база для власних реалізацій; чому вони не конфліктують.
- [x] Інтерфейс vs абстрактний клас з TS/Java і чому в Python "інтерфейс" це Protocol, а ABC ближче до абстрактного класу.
- [x] `NotImplementedError` проти `@abstractmethod`: одне речення (посилання на m4-l04).
- [x] Для капстоуну: `BaseRenderer(ABC)` з template method `render_tree` і абстрактними `render_element`/`wrap_page`; `Renderer` Protocol з m2-l07 лишається типом параметра у воркері.
- [x] Які JS-звички тут шкодять: `interface` з `implements` як єдиний спосіб, абстрактні класи TS без рантайм-перевірки, очікування, що ABC без `@abstractmethod` щось перевіряє.
