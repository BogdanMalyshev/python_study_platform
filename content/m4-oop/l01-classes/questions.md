# Ключові питання уроку m4-l01 "Класи, __init__, self, атрибути класу й екземпляра"

Урок готовий, коли на кожне питання є відповідь з кодом і виводом. dataclasses уже відомі з m2-l05; тут механізм звичайних класів.

- [x] `class`, `__init__` як ініціалізатор (не конструктор: `__new__` одним реченням), `self` як явний перший параметр і чому він явний. Порівняти з `constructor` і `this`, де `this` залежить від способу виклику, а `self` ні.
- [x] Атрибути екземпляра (`self.x = ...` у будь-якому методі) проти атрибутів класу (визначені в тілі класу); пошук атрибута: екземпляр → клас → батьки; пастка змінюваного атрибута класу, спільного для всіх екземплярів. Аналог static і полів класу в TS.
- [x] Методи, `@classmethod` (альтернативні конструктори `from_dict`, `cls`), `@staticmethod` (і чому часто краще функція модуля). Bound і unbound методи: `obj.method` це функція з прив'язаним `self`, `Class.method(obj)` еквівалент (посилання з m1-l09 сюди).
- [x] Немає `private`/`public`: конвенція `_x`, name mangling `__x` → `_Class__x` і для чого воно насправді (уникнення конфліктів при наслідуванні, не приватність). Чому Python довіряє розробнику.
- [x] `__dict__` екземпляра і класу, динамічне додавання атрибутів, `vars`, `getattr`/`setattr`/`hasattr`, `__slots__` одним реченням (детально m4-l03). Чому екземпляр "важчий" за dataclass зі slots.
- [x] `__repr__` одразу: без нього `print(obj)` дає адресу; мінімальний `__repr__` як звичка (детально dunder у m4-l02).
- [x] Все є об'єкт: клас це об'єкт типу `type`, його можна передати, покласти в словник, створити динамічно; `type(obj)`, `obj.__class__`, `isinstance`, `issubclass`. Одне речення про метакласи без деталей.
- [x] Коли клас, а не функції + словник: стан + поведінка разом, інваріанти, кілька реалізацій одного інтерфейсу (посилання на m2-l07 і m4-l08). Чому в Python менше класів, ніж у типовому TS-коді.
- [x] Анотації атрибутів у тілі класу без значення (`name: str`) не створюють атрибут, лише анотацію; різниця з dataclass, де це поле.
- [x] Для капстоуну: клас `GenerationJob` зі станом (`id`, `config`, `status`, `attempts`), методами `start`, `fail`, `succeed`, `from_config` як classmethod, лічильник створених задач як атрибут класу.
- [x] Які JS-звички тут шкодять: `this` з arrow-функціями, `private`/`#x`, геттери як у TS (тут `property`, m4-l03), `static` для утиліт, оголошення полів у тілі класу як у TS (`x = []` стане спільним), `new`.
