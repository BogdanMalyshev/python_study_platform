# Ключові питання уроку m2-l01 "list, tuple, dict, set проти Array, Object, Map, Set"

Урок готовий, коли на кожне питання є відповідь з кодом і виводом.

- [x] Чотири вбудовані колекції й їхні ролі: `list` (змінювана послідовність), `tuple` (незмінна послідовність, часто "запис"), `dict` (відображення), `set` (унікальні елементи). Таблиця відповідностей з JS і де відповідність неточна (`Object` це не `dict`, `tuple` аналога не має, `Map` найближчий до `dict`).
- [x] list: літерал, `append`, `extend`, `insert`, `pop`, `remove`, `index`, `count`, `sort`/`sorted`, `reverse`/`reversed`, `+`, `*`, `in`, `len`. Що повертає кожен метод (`append` повертає `None`). Відповідності `push`/`pop`/`splice`/`indexOf`/`includes`.
- [x] tuple: літерал з комою (`(1,)`, `1,`), розпакування, незмінність елементів, але не вмісту (`([1], 2)`), як ключ словника, повернення кількох значень з функції. Чому tuple, а не list, для "запису фіксованої форми"; namedtuple одним реченням з посиланням на m2-l04.
- [x] dict: літерал, `d[key]` кидає `KeyError`, `d.get(key, default)`, `setdefault`, `keys`/`values`/`items` як view-об'єкти (живі, не копії), `in` перевіряє ключі, `del`, `pop`, `update`, `|` для злиття (3.9+). Порядок вставки гарантований з 3.7. Ключем може бути будь-який hashable (tuple так, list ні), і чому.
- [x] Чим `dict` відрізняється від JS `Object`: ключі будь-якого типу, немає прототипу, `1` і `"1"` різні ключі, `True` і `1` один ключ, немає крапкової нотації (`d.key` це `AttributeError`). І від `Map`: літерал, comprehension, JSON напряму.
- [x] set: літерал `{1, 2}`, порожній лише `set()`, `add`, `discard`/`remove`, операції `|`, `&`, `-`, `^`, `issubset`, `in` за O(1). Дедуплікація зі збереженням порядку через `dict.fromkeys`. frozenset одним реченням.
- [x] Hashability: чому `list` не може бути в `set` і ключем `dict`, `TypeError: unhashable type`, як `__hash__` пов'язаний з `__eq__` (одне речення, детально в m4-l02), і чому tuple зі списком усередині теж unhashable.
- [x] Вибір структури: list для порядку і дублікатів, set для членства, dict для пошуку за ключем, tuple для незмінного запису. Складність базових операцій (`in` для list O(n), для set/dict O(1)) з одним вимірюванням.
- [x] Вкладені структури: список словників, словник списків, доступ `config["elements"][0]["name"]`, і чому `KeyError`/`IndexError` замість `undefined` (посилання на m1-l11).
- [x] JSON: `json.loads` дає dict/list/str/int/float/bool/None, `json.dumps` з `indent`, `ensure_ascii=False` для української, `sort_keys`. tuple серіалізується як список, set не серіалізується.
- [x] Для капстоуну: конфіг форми як вкладений dict, індекс елементів за `name` як dict, множина обов'язкових полів як set, кортеж `(page, order)` як ключ сортування.
- [x] Які JS-звички тут заважають: `obj.key`, `arr.length`, `arr.push`, `Object.keys(d)` замість `d.keys()` або просто `d`, `[...new Set(arr)]`, `Array.isArray`, `JSON.parse` без очікування, що ключі лишаться рядками (у dict вони будуть рядками, бо JSON, але `d[1]` і `d["1"]` різні).
