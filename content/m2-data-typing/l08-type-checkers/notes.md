# Нотатки до m2-l08 "mypy і pyright у strict-режимі"

## Що запускалось

Середовище: `.venv/bin/python` (Python 3.12.12) і `.venv/bin/mypy` (mypy 2.4.0, compiled: yes) з кореня проєкту;
uv 0.9.28. Усі тимчасові файли лежали в `<scratchpad>/m2-l08/`, після перевірки ця підпапка видалена.
У виводах в уроці абсолютні шляхи scratch-директорії замінено на базові імена файлів або шляхи від кореня
тимчасового проєкту; більше нічого у виводах не змінювалось.

- Усі приклади з mypy-виводом у `lesson.md` (runtime.py, config.py на чотирьох рівнях суворості, `--pretty`,
  `--show-column-numbers`, `--hide-error-codes`, reexport/strict-equality, конфіг з overrides і `warn_unused_configs`,
  пастка `tests.*` без `__init__.py`, narrowing.py, match_narrow.py, limits.py, closure.py, unsound.py, fixed.py,
  шість повідомлень і їх виправлення, any_param.py, ignores.py з `--enable-error-code ignore-without-code`, casts.py,
  revealrt.py, циклічний імпорт з `TYPE_CHECKING` і без, uses_libs.py, uses_legacy.py у трьох варіантах, compare.py,
  notests.py, assert_o.py з `-O`) запущено окремими файлами; вивід вставлено дослівно.
- Після запису `lesson.md` скрипт витягнув із нього всі блоки: 3 блоки ```` ```python live ```` виконано й звірено
  з наступним ```` ```text ````; 15 блоків, за якими йде `$ mypy [--strict] файл.py`, записано у файли з тими самими
  іменами й перевірено mypy. Збіг повний, крім трьох очікуваних випадків: `fixed.py` у уроці показано фрагментом
  (Field і reset з попереднього блоку), а `uses_legacy.py` і стаб `.pyi` потребують окремого оточення; ці три
  перевірено окремо на повних файлах.
- `uses_legacy.py`: щоб показати `import-untyped` для встановленого пакета без `py.typed`, у scratch створено окреме
  оточення (`uv venv`) з фейковим пакетом `legacy_forms` у site-packages і `types-PyYAML` (`uv pip install`, у
  `.venv` проєкту нічого не ставилось). mypy запускався з `--python-executable <scratch>/venv/bin/python`; в уроці
  команда показана без цього прапорця, бо в реальному проєкті бібліотека стоїть у тому самому оточенні.
- Капстоун: `capstone/` створює паралельно інший агент, я його не чіпав і `cd capstone && uv run mypy src` не
  запускав. Замість цього в scratch зібрано копію скелета за описом m0-l06 (`src/formbuilder/{__init__,cli,__main__}.py`,
  `tests/test_smoke.py`, uv_build), виконано `uv add --dev mypy pytest`, додано той самий блок `[tool.mypy]`, що в
  уроці, і запущено `uv run mypy src` та `uv run mypy` до й після виправлень, плюс `uv run pytest -q`,
  `uv run python -m formbuilder`, `uv run formbuilder --version`. Виводи в розділі "Для капстоуну" саме звідти.
  Номери рядків у помилках залежать від того, як саме написано `cli.py` у справжньому скелеті.
- pyright: одна спроба `uvx pyright@latest --version` спрацювала (pyright 1.1.414, пакет 5.9 MiB з PyPI у кеш uv,
  глобально нічого не встановлено). Використано рівно для одного порівняння: `uvx pyright@latest compare.py` у режимі
  за замовчуванням (`standard`) проти `mypy compare.py`. Решта про pyright і Pylance (`typeCheckingMode` у
  `[tool.pyright]`, `python.analysis.typeCheckingMode` у VS Code, значення за замовчуванням `off` у Pylance,
  narrowing збережених умов) описано за документацією, не запуском.
- `tasks.yaml`: розпарсено `yaml.safe_load`; для t1–t3 `solution + harness` виконано й звірено з `expected` після
  нормалізації (усі три збігаються); кожне рішення разом з харнесом проходить `mypy --strict`; `starter` компілюється.
  Фрагменти з квізів q1–q4 запущено через mypy (і python для q2, q3), відповіді звірені з реальним виводом, зокрема
  для q3 перевірено всі чотири варіанти: ignore і cast проходять mypy і падають з `AttributeError`, анотація змінної
  дає `assignment`. Перевірено, що кожен id з `tasks.yaml` вставлений у `lesson.md` рівно один раз.
- Додатково перевірено, але в урок не включено: Pydantic v2 моделі mypy перевіряє без плагіна (`call-arg`, `arg-type`
  однакові з `plugins = ["pydantic.mypy"]` і без нього), про це одне речення в callout для капстоуну.

## Рішення

- Розділів `##` дванадцять: вісім теоретичних (верхня межа спеки), `Для капстоуну` і три обов'язкові. Конфіг виділено
  в окремий розділ, бо він сам по собі питання з `questions.md` і аналог `tsconfig.json`.
- Обсяг: 45 абзаців теорії плюс 4 у розділі для капстоуну і 5 callout-блоків. Це вище орієнтира 40, але нижче 50.
  Якщо урок здасться задовгим, природний шов: "Сторонні бібліотеки, редактор і CI" разом з "Для капстоуну" і p1/p2 як
  окремий урок "mypy у проєкті" (інфраструктура), а все про читання повідомлень, narrowing і аварійні виходи лишається
  тут. Урок здано цілим.
- Завдання: 3 code (browser), 4 quiz, 2 project. Бриф просив переважно quiz і project; спека вимагає 3–6 code і 2–4
  quiz, тож узято мінімум code і максимум quiz. Code-завдання показують narrowing у рантаймі (ранній return,
  `match` + `assert_never`, `isinstance` замість `cast`), а в умовах сказано, що рішення мають проходити `mypy --strict`.
- Про звуження атрибута після виклику функції `questions.md` формулює "де не звужує (атрибут об'єкта після виклику
  функції)". Реальна поведінка mypy 2.4 протилежна: звуження атрибута переживає виклик (unsound), а не звужується
  результат виклику методу. Урок показує обидва факти з виводом mypy і рантаймом, і ліки ті самі, що в питанні
  (локальна змінна, walrus). Квіз q2 побудовано саме на цьому.
- `--strict` у mypy 2.4 вмикає 13 прапорців (список з `mypy --help`), `warn_unused_configs` серед них уже немає, тому
  в конфігу він записаний явно. `ignore-without-code` не входить у strict, у конфіг капстоуну додано
  `enable_error_code = ["ignore-without-code"]`.
- Молоді чекери ty і pyrefly згадано одним реченням без характеристик, бо їх не запускав.
- `TypeGuard`/`TypeIs`, `@overload`, `Any` проти `object` у подробицях не розкривались: це m2-l06, тут по одному
  реченню з посиланням. `Protocol` (m2-l07) в уроці не використано зовсім.
- pre-commit і CI описано одним абзацом з посиланням на m3-l06; YAML хуків і workflow не показано, щоб не дублювати.

## Незакриті питання

Усі 11 питань з `questions.md` закриті. Застереження: питання про pyright закрито одним реальним порівнянням і
описом за документацією, як дозволяв бриф; конфіг `[tool.pyright]` і налаштування Pylance не запускались.

## Залежності

- Спирається на m2-l06 (синтаксис анотацій, `X | None`, `Literal`, `TypedDict`, `Any`/`object`, відкладені анотації),
  m2-l07 (формально пререквізит; Protocol не використовується), m0-l04 (ruff як контраст), m0-l06 (скелет капстоуну),
  m1-l05 (`match`), m1-l06 (walrus).
- Готує для m2-l09 (Pydantic як відповідь на `Any` з `json.loads`; strict-конфіг перевірятиме моделі), m3-l03 (тести
  поверх типів), m3-l06 (`uv run mypy` у pre-commit), m6-l06 (`argparse.Namespace` як `Any`, Typer / Pydantic для CLI).
- Капстоун після p1/p2: `[tool.mypy]` зі strict, `files = ["src", "tests"]`, `py.typed`, mypy у dev-залежностях.
