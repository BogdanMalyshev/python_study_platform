# Ключові питання уроку m2-l07 "Protocol: структурна типізація, duck typing офіційно"

Урок готовий, коли на кожне питання є відповідь з кодом, виводом і реальним виводом `mypy` (встановлений у `.venv`).

- [x] Duck typing як норма Python: функція працює з будь-чим, що має потрібний метод, без наслідування; `len(x)` працює через `__len__`, `for` через `__iter__`. Чому це те саме, що структурна типізація TS, лише без статичної перевірки.
- [x] `typing.Protocol`: оголошення інтерфейсу за формою, клас не мусить наслідувати Protocol, щоб йому відповідати. Показати `mypy` вивід для класу, що відповідає, і для класу, що ні. Аналог TS interface один в один.
- [x] Protocol проти ABC: номінальна (треба наслідувати, `@abstractmethod`, не можна створити екземпляр без реалізації) проти структурної (нічого не треба). Коли ABC (власна ієрархія, потрібна перевірка в рантаймі), коли Protocol (чужі класи, функції-параметри). Детально ABC у m4-l05.
- [x] `@runtime_checkable` і `isinstance(obj, Proto)`: перевіряє лише наявність методів, не сигнатури; коли це корисно і де обманює.
- [x] Protocol з атрибутами, з `@property`, з `__call__` для типізації функцій за формою (альтернатива `Callable`), generic Protocol.
- [x] Вбудовані протоколи з `collections.abc` і `typing`: `Iterable`, `Iterator`, `Sized`, `Container`, `Hashable`, `SupportsInt`, `SupportsFloat`. Чому параметр функції краще анотувати `Iterable[str]`, а не `list[str]` (приймає tuple, set, generator).
- [x] Протоколи, що стоять за операторами й синтаксисом: `__len__`, `__iter__`, `__getitem__`, `__contains__`, `__bool__`, `__enter__`/`__exit__`. Одне речення й посилання на m4-l02 і m4-l07.
- [x] Як mypy перевіряє відповідність Protocol: ковариантність повернення, контраваріантність параметрів (одне речення без теорії), типова помилка "incompatible type" через інакшу сигнатуру методу.
- [x] Явна відповідність для документації: клас може наслідувати Protocol явно, і тоді mypy перевірить реалізацію на місці оголошення, а не на місці використання.
- [x] Для капстоуну: `Renderer` Protocol з методом `render(element, theme) -> str`, кілька реалізацій (HTML, текстовий для тестів) без спільного базового класу, реєстр рендерерів типізований як `dict[str, Renderer]`.
- [x] Які JS-звички тут заважають: `implements` як обов'язок, очікування, що без `implements` клас "не того типу", пошук `interface` ключового слова, `instanceof` для перевірки інтерфейсу.
