# Ключові питання уроку m2-l02 "Змінюваність, aliasing, copy і deepcopy"

Урок готовий, коли на кожне питання є відповідь з кодом і виводом.

- [x] Модель даних Python: змінна це ім'я, прив'язане до об'єкта; присвоєння не копіює. `id()`, `is`, два імені на один об'єкт (aliasing). Та сама модель, що в JS для об'єктів, але без винятку для примітивів, бо примітиви незмінні.
- [x] Незмінні типи (`int`, `float`, `str`, `tuple`, `frozenset`, `bytes`) проти змінюваних (`list`, `dict`, `set`, об'єкти класів). Що означає `x += 1` для int (новий об'єкт) і `lst += [1]` для list (той самий об'єкт, виклик `__iadd__`). Показати через `id`.
- [x] Пастка `+=` на кортежі зі списком усередині: `t = ([1], 2); t[0] += [3]` кидає `TypeError`, але список таки змінюється. Пояснити чому.
- [x] Aliasing у функціях: аргумент-список мутується всередині й видно ззовні; переприсвоєння параметра ззовні не видно. Правило "мутувати або повертати нове, але не обидва мовчки".
- [x] Aliasing у структурах: `[[0] * 3] * 3`, `dict.fromkeys(keys, [])`, `a = b = []`, mutable default (посилання на m1-l07). Як діагностувати (`id`, `is`) і як правильно (comprehension, `default_factory`).
- [x] Поверхнева копія: `list(x)`, `x[:]`, `x.copy()`, `dict(d)`, `d.copy()`, `copy.copy`. Що копіюється (контейнер), що ні (елементи). Аналог spread `[...arr]`, `{...obj}`.
- [x] Глибока копія: `copy.deepcopy`, як обробляє цикли, чому повільна, коли потрібна. Аналог `structuredClone`. Трюк `json.loads(json.dumps(x))` і чому він гірший.
- [x] Незмінні версії змінюваних: `tuple(lst)`, `frozenset(s)`, `types.MappingProxyType(d)` для read-only view словника. Чому "незмінність" у Python це про тип, а не про `const`/`Object.freeze`.
- [x] Кортеж незмінний, але його елементи можуть бути змінюваними; "незмінність" неглибока. Коли tuple як ключ словника раптом ламається.
- [x] Рядки: кожна операція створює новий об'єкт, `s += "x"` у циклі (посилання на m1-l04), інтернування як деталь реалізації (посилання на m1-l03).
- [x] Для капстоуну: конфіг форми приходить як dict і проходить через кілька етапів (нормалізація, валідація, рендер). Правило: кожен етап повертає новий об'єкт або явно документує мутацію; `deepcopy` на вході API, щоб не зіпсувати оригінал. Показати баг, коли нормалізація мутує вхідний конфіг.
- [x] Які JS-звички тут заважають: `const` як "незмінний", `Object.freeze` як глибока заморозка, `[...a]` як глибока копія, очікування, що примітиви "копіюються", а об'єкти "за посиланням" (у Python усе за посиланням, різниця лише в змінюваності).
