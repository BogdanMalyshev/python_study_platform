# Ключові питання уроку m7-l04 "WebSocket у FastAPI для статусу генерації"

Урок готовий, коли на кожне питання є відповідь з кодом і виводом. Той самий режим, що m7-l01. Учень знає socket.io з боку клієнта і сервера; тут сирий WebSocket у FastAPI.

- [x] `@app.websocket("/ws/jobs/{job_id}")`, `await websocket.accept()`, `receive_text`/`send_json`, `WebSocketDisconnect`; життєвий цикл з'єднання. Порівняти з socket.io: немає кімнат, подій і автоперепідключення з коробки, є лише повідомлення.
- [x] Стрімінг статусів: асинхронний генератор подій задачі (посилання на m5-l06) → `async for event in events(job_id): await ws.send_json(event)`; завершення після `done`/`failed`.
- [x] Одночасні читання й запис: `TaskGroup` з двома задачами (слухати клієнта і слати події), скасування при розриві (посилання на m5-l05), heartbeat/ping.
- [x] Менеджер з'єднань: словник `job_id → set[WebSocket]`, broadcast, прибирання при відключенні, пастка з мутацією set під час ітерації (посилання на m1-l06).
- [x] Протокол повідомлень: Pydantic-моделі подій з `type` і discriminated union (посилання на m2-l09), `model_dump_json`, версія протоколу; валідація вхідних повідомлень від клієнта.
- [x] Автентифікація на WebSocket: токен у query або першому повідомленні, `Depends` працює і тут; лише механіка, без теорії auth.
- [x] Альтернатива: Server-Sent Events через `StreamingResponse` для односторонніх статусів, коли WS зайвий; порівняти в три рядки.
- [x] Тестування: `TestClient.websocket_connect` як контекстний менеджер, `receive_json`, fake-джерело подій (посилання на m7-l05).
- [x] Масштабування понад один процес: чому broadcast не працює між uvicorn-воркерами і одне речення про Redis pub/sub як рішення поза курсом.
- [x] Для капстоуну: ендпоінт `/ws/jobs/{id}`, який віддає `queued → running → done` з прогресом сторінок, менеджер з'єднань, тест через `websocket_connect`; мінімальний HTML-клієнт на 15 рядків для перевірки руками.
- [x] Які JS-звички тут шкодять: `socket.emit("event", data)` з іменованими подіями (тут один канал повідомлень з полем `type`), `io.to(room)`, автоматичний reconnect, `ws.on("message")` колбеки замість `async for`.
