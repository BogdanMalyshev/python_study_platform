# Ключові питання уроку m7-l06 "Jinja2: шаблони як простий рендерер статики"

Урок готовий, коли на кожне питання є відповідь з кодом і виводом. Jinja2 не в Pyodide платформи: приклади non-live з локальним виводом (встановити jinja2 лише у scratch venv), завдання `type: project` у капстоуні, у браузері quiz і чисті функції (екранування, побудова контексту). Короткий урок: 25–30 абзаців.

- [x] Навіщо шаблонізатор, коли є f-рядки: екранування HTML за замовчуванням (XSS), цикли й умови в розмітці, наслідування шаблонів. Порівняти з JSX/React SSR і з Handlebars/Nunjucks (Nunjucks це порт Jinja2).
- [x] `Environment(loader=PackageLoader("formbuilder", "templates"), autoescape=select_autoescape())`, `get_template`, `render(**context)`; шаблони як ресурси пакета (посилання на m3-l02, m6-l01).
- [x] Синтаксис: `{{ }}`, `{% for %}`, `{% if %}`, фільтри (`|e`, `|default`, `|join`, власні через `env.filters`), `{% macro %}` для повторюваних елементів форми, `{% extends %}`/`{% block %}` для базової сторінки, `{% include %}`.
- [x] Автоекранування і `Markup`/`|safe`: коли вимикати і чому майже ніколи; що відбувається з user-content у label елементів.
- [x] Контекст: dataclass-об'єкти доступні через крапку, dict через крапку або `[]`, `Undefined` і `StrictUndefined` для раннього виявлення помилок, `None` у шаблоні.
- [x] Рендер дерева елементів: рекурсивний macro або `{% for %}` з `loop.depth`, диспетчеризація за `type` через `{% if %}` або словник шаблонів; critical CSS інлайн як у FormBuilder (одне речення).
- [x] Продуктивність: кеш скомпільованих шаблонів в `Environment` (один на застосунок), `render` у `to_thread` при великих обсягах (посилання на m5-l08).
- [x] Тестування рендера: порівняння з еталонним HTML у `tests/fixtures`, нормалізація пробілів, перевірка екранування.
- [x] Для капстоуну: `JinjaRenderer` як реалізація `Renderer` Protocol (посилання на m2-l07): `base.html`, `form.html`, macro на кожен тип елемента, тема в CSS-змінних, adaptive через breakpoints; підключення до воркера (посилання на m7-l03).
- [x] Які JS-звички тут шкодять: JSX-мислення (компоненти з логікою), `dangerouslySetInnerHTML` як норма, `{{ }}` з довільним JS (тут обмежений вираз), шаблонні рядки без екранування.
