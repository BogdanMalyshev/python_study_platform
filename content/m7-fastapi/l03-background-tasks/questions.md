# Ключові питання уроку m7-l03 "Фонові задачі: BackgroundTasks і воркер на asyncio.Queue"

Урок готовий, коли на кожне питання є відповідь з кодом і виводом. Той самий режим, що m7-l01. Черги як інфраструктура (Redis, Celery) не викладаються: лише те, що робиться засобами Python у одному процесі, з одним реченням про межу.

- [x] `BackgroundTasks` у FastAPI: `background_tasks.add_task(fn, arg)`, виконання після відповіді, обмеження (той самий процес, втрачається при рестарті, немає ретраїв); коли цього достатньо (лист, лог) і коли ні (генерація сторінок).
- [x] Воркер у процесі: `asyncio.Queue` + N воркерів, запуск у `lifespan` (посилання на m7-l01, m5-l05), graceful shutdown через скасування (посилання на m6-l07), обмеження паралелізму `Semaphore`.
- [x] Стан задачі між запитами: in-memory dict проти SQLite `JobStore` (посилання на m6-l08); чому після рестарту задачі з `running` треба повертати в `queued`.
- [x] Ретраї й помилки: лічильник спроб, експоненційна затримка (посилання на m5-l04 `@retry`), остаточний `failed` з повідомленням, ідемпотентність задачі (повторний запуск не ламає результат).
- [x] CPU-важкий рендер у воркері: `to_thread` або `ProcessPoolExecutor` (посилання на m5-l08), і як це поєднується з `asyncio.Queue`.
- [x] Сповіщення про прогрес: callback-список (Observer з m4-l08) або `asyncio.Queue` подій на задачу, які споживає WebSocket (посилання на m7-l04).
- [x] Межа одного процесу: кілька uvicorn-воркерів мають окремі черги; коли переходити на окремий процес-воркер з SQLite як чергою, і одне речення про Redis/arq/Celery як наступний крок поза курсом.
- [x] Тестування воркера: fake-рендерер, `asyncio`-тест з `pytest-asyncio`/`anyio` (посилання на m7-l05), перевірка переходів статусів без реального сну (інʼєкція `sleep`).
- [x] Для капстоуну: `POST /forms/{id}/build` кладе задачу в `JobStore` і `Queue`; воркер бере, рендерить через `Renderer`, публікує через `Publisher`, оновлює статус; `GET /jobs/{id}` читає зі сховища; graceful shutdown.
- [x] Які JS-звички тут шкодять: `setImmediate`/fire-and-forget промісів, BullMQ як перший рефлекс, очікування, що фоновий таск переживе процес, worker_threads для черги.
