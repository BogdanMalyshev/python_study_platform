# Ключові питання уроку m7-l05 "Тести API: pytest і httpx AsyncClient"

Урок готовий, коли на кожне питання є відповідь з кодом і виводом. Той самий режим, що m7-l01: усі приклади запускаються локально через pytest з реальним виводом; завдання проєктні в капстоуні.

- [x] `TestClient` (синхронний, на httpx) проти `httpx.AsyncClient(transport=ASGITransport(app=app))` для async-тестів; коли який; `base_url`.
- [x] Асинхронні тести: `pytest-asyncio` з `asyncio_mode = "auto"` або `anyio` плагін (йде з FastAPI/httpx), `@pytest.mark.anyio`, фікстура `anyio_backend`; одна з двох схем обрана для капстоуну з поясненням.
- [x] Фікстури застосунку: `app` з `lifespan` (`async with LifespanManager` або TestClient як контекстний менеджер), `client` фікстура, `dependency_overrides` для сховища й налаштувань (посилання на m7-l01, m3-l03).
- [x] Ізоляція стану: SQLite `:memory:` або `tmp_path` на тест (посилання на m6-l08), fake `Renderer`/`Publisher` через Protocol (посилання на m2-l07, m3-l04), без реального воркера або з воркером, що викликається вручну.
- [x] Що перевіряти: статус, тіло через `response.json()`, помилки 422 і власний формат (посилання на m7-l02), заголовки, OpenAPI-схема як snapshot одним реченням.
- [x] Параметризовані тести валідації конфігів (посилання на m3-l03) через API, фабрики тестових конфігів.
- [x] Тестування WebSocket через `websocket_connect` (посилання на m7-l04), тестування фонових задач без сну: інʼєкція `sleep`, запуск воркера на один крок.
- [x] Структура тестів у капстоуні: `tests/test_api_forms.py`, `tests/test_api_jobs.py`, `conftest.py` з фікстурами, маркери `slow`; coverage API (посилання на m3-l04).
- [x] Для капстоуну: повний сценарій тестом: створити форму → запустити build → воркер крок → статус done → статика існує у `tmp_path`; тест на невалідний конфіг → 422 у власному форматі.
- [x] Які JS-звички тут шкодять: supertest-ланцюжки, `beforeAll` з реальним сервером на порту, моки на рівні HTTP-бібліотеки замість `dependency_overrides`, jest timers для фонових задач.
