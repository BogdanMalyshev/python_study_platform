# Ключові питання уроку m0-l03 "REPL, запуск скриптів, python -m, __main__"

Урок готовий, коли на кожне питання є відповідь з командами і реальним виводом.

- [x] REPL: `python`, що робить `>>>` і `...`, автоматичний вивід значень виразів без `print`, `_` як останній результат, `help(obj)`, `dir(obj)`, Ctrl-D. Чим REPL 3.13 (кольори, багаторядкове редагування) відрізняється від 3.12, одне речення. Порівняти з `node` REPL.
- [x] Запуск файлу: `python script.py`, `python -c "..."`, `python -i script.py` (REPL після виконання), `python -u` (без буферизації, навіщо в Docker і CI).
- [x] `python -m module`: запуск модуля як скрипта за іменем, а не шляхом (`python -m pytest`, `python -m http.server`, `python -m json.tool`, `python -m venv`). Чому `python -m pip` надійніше за `pip`. Аналог `npx` частково.
- [x] `__name__`: чому дорівнює `"__main__"` при прямому запуску й імені модуля при імпорті; ідіома `if __name__ == "__main__": main()` і навіщо функція `main()`. Показати обидва випадки на двох файлах з реальним виводом.
- [x] `sys.argv`, базові аргументи командного рядка без argparse (детально в m6-l06). `sys.exit(code)` і код завершення, перевірка `echo $?`.
- [x] Як Python шукає модулі при `import`: `sys.path`, поточна директорія скрипта на першому місці, `PYTHONPATH`. Чому `python src/app/main.py` і `python -m app.main` дають різний `sys.path` і різні результати імпортів (підготовка до m0-l06 і m3-l01).
- [x] Байткод і `__pycache__`: що компілюється, коли, і чому це не "компіляція" у звичному сенсі. `python -O` і `assert`. Одне речення про `.pyc`.
- [x] Змінні оточення, які варто знати: `PYTHONPATH`, `PYTHONDONTWRITEBYTECODE`, `PYTHONUNBUFFERED`, `PYTHONWARNINGS`. Де вони знадобляться (Docker, CI).
- [x] Jupyter і IPython як альтернативний REPL: одне речення, для чого і що не для цього курсу.
- [x] Які JS-звички тут заважають: `node file.js` з будь-якої папки і очікування, що імпорти відносні до файлу; `require.main === module` знайоме, але пишуть `__name__ == "main"` без підкреслень; очікування `process.argv[2]` замість `sys.argv[1]`.
