# Нотатки до m0-l01

## Що запускалось

Машина: macOS 26.6.2, zsh, uv 0.9.28, системний `/usr/bin/python3` 3.9.6 (Xcode CLT 26.5), Homebrew 7.0.4 з
`python@3.14` 3.14.5 і `python@3.11` 3.11.15, uv-керовані CPython 3.12.12 і 3.10.19, nvm 0.40.3, Node 24.9.0.
Нічого нового глобально не встановлювалось; `.venv` курсу лише читався (`pyvenv.cfg`, `--version`).

- Усі `bash`-блоки теорії зібрано в один zsh-скрипт і повторно виконано в робочій підпапці scratch-директорії
  `<scratchpad>/m0-l01/run/` у тому порядку, як їх виконував би учень (з `versions-demo` як каталогом проєкту).
  Вивід звірено з `text`-блоками уроку. Окремо: `head -1 .venv/pyvenv.cfg` з кореня курсу; `nvm ls` через
  `zsh -i`; рядки `zsh: command not found: python` і сесія REPL записані через `script` у справжньому pty,
  щоб вивід збігався з інтерактивним терміналом, а не з `zsh -c` (там префікс `zsh:1:`).
- `python`-блоки (`sys.version_info`, порівняння рядків і кортежів, приклад з помилки 5) через `.venv/bin/python`;
  `ann.py` через системний 3.9 і `uv run --python 3.12`; `ts`-блок через `node` 24.9.0.
- `pip install` на системному і Homebrew-Python без `--dry-run` не запускався: це змінило б глобальний стан.
  PEP 668 показано через `pip install --dry-run` на Homebrew 3.14 (відмова відбувається до мережі) і
  `uv pip install --system --dry-run` на uv-3.12 (той самий маркер). Поведінку Apple-івського pip 21.2.4
  ("Defaulting to user installation...") перевірено викликом `pip._internal.commands.install.decide_user_install(None)`
  з увімкненим logging і за вихідним кодом pip, без реальної установки.
- `.exit` у REPL, `exit` без дужок у 3.12 і в 3.14 (виходить) перевірено в pty.
- Твердження про `pyvenv.cfg` Homebrew перевірено створенням тимчасового venv у scratch: `home` вказує на
  `/opt/homebrew/opt/python@3.14/bin`, а не на `Cellar/.../3.14.5`. Через це текст "Під капотом" каже,
  що патч-оновлення оточення переживає, а ламається воно при видаленні всієї гілки `python@3.14`.
- `tasks.yaml`: розпарсено `yaml.safe_load`; кожне `solution + harness` трьох code-завдань виконано і звірено з
  `expected` після нормалізації; `starter + harness` дає інший вивід. Для t2 окремо перевірено, що наївне
  `version >= minimum` дає розбіжність у двох рядках. Обидва `verify` проєктних завдань прогнано на еталонному
  рішенні в scratch-копії кореня курсу (`practice/m0-l01/` + симлінк `.venv`): на порожньому каталозі обидва
  падають, на рішенні проходять, при `.python-version = 3.10` p2 падає. p1 після появи `pyproject.toml` з p2
  у тому самому каталозі теж проходить: `uv run --script` проєкт ігнорує.
- Кожен маркер `<!-- task: ... -->` перевірено на рівно одне входження.

Scratch-підпапку `<scratchpad>/m0-l01/` після перевірки видалено.

## Рішення

- Вивід у кількох місцях скорочено, і в тексті уроку це сказано: `python3 -m site`, повний текст відмови pip,
  `nvm ls`, `import this`, traceback 3.9 і `distutils`, довгі шляхи scratch-директорії в `which_python.py`
  замінено на `…/versions-demo`. Шляхи `/Users/mac/...` лишились справжніми: урок для однієї машини.
- Питання 1 у `questions.md` припускає, що системний 3.9 захищений PEP 668. На цій машині це не так: маркера
  `EXTERNALLY-MANAGED` в Apple-івського 3.9 немає, pip тихо ставить у user site. Урок показує обидва випадки
  (Apple без маркера, Homebrew і uv з маркером) і робить з цього окрему пастку та quiz q1. Реальний стан
  `~/Library/Python/3.9` учня (100 пакетів, 48 команд) використано як приклад забруднення.
- pyenv на машині не встановлений, тому його команди (`pyenv install`, `pyenv global`) згадані лише в тексті й
  таблиці порівняння, без `bash`-блоків і без виводу. Це сказано в уроці прямо.
- Віртуальне оточення, `uv.lock`, `uv add`, `uvx`, `uv tool install` згадані одним реченням з посиланням на m0-l02.
  `.venv` і `uv.lock` у виводі `uv run` не пояснюються, лише називаються. `python3 -m venv` використано один раз,
  щоб показати `pyvenv.cfg` Homebrew-Python.
- PEP 723 (inline script metadata) і shebang `#!/usr/bin/env -S uv run --script` дано тут, бо питання про
  shebang без них не має доброї відповіді на macOS; у m0-l02 його в списку питань немає.
- REPL: лише запис сесії, `exit()`, Ctrl-D, `exit` у 3.13+, `.exit` як JS-звичка. Решта в m0-l03.
- Окремого розділу `## Для капстоуну` немає: тема дотична до капстоуну лише через пін версії, тож це один
  callout `Для капстоуну` у розділі про `.python-version` (Dockerfile у m7-l07, репозиторій у m0-l02).
- Завдання: 3 code (`runtime: browser`, stdlib), 4 quiz, 2 project з `verify`. Code-завдання не про синтаксис
  взагалі, а про версії: форматування `sys.version_info`, порівняння версій кортежами, розбір виводу
  `uv python list` з числовим сортуванням. t1 у харнесі звіряє результат зі справжнім `sys.version`
  інтерпретатора, тому детерміновано дає `True` і в `.venv` (3.12.12), і в Pyodide (3.12.x).
  Проєктні завдання працюють у `practice/m0-l01/` у корені курсу, а не в репозиторії капстоуну, бо його ще немає.
  `verify` p1 запускається з кореня курсу; p2 про uv, тому робить `cd practice/m0-l01 && uv run ...` (конвенція
  з `docs/lesson-spec.md` для uv-завдань модуля 0).
- Обсяг: 7 теоретичних розділів + 3 обов'язкові, 37 абзаців прози без callout-ів, таблиці й списків, у межах 20–40.
  Максимум підряд 3 текстові блоки без коду чи завдання.
- Дати релізів і підтримки (PEP 602: жовтень, 5 років; 3.9 EOL жовтень 2025) подано як факти без коду;
  кодом підкріплено наслідки: 3.9 не розбирає `dict | None`, `distutils` зник у 3.12.
