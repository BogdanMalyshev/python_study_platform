# Ключові питання уроку m3-l04 "Моки: unittest.mock, pytest-mock; coverage"

Урок готовий, коли на кожне питання є відповідь з кодом і виводом.

- [x] Коли мок потрібен (зовнішній I/O, час, випадковість, мережа) і коли це запах (мокання власного коду замість рефакторингу під інʼєкцію залежностей). Чому в Python моків менше, ніж у JS: duck typing дозволяє передати будь-який об'єкт.
- [x] `unittest.mock.Mock` і `MagicMock`: будь-який атрибут і виклик існують, `return_value`, `side_effect` (значення, виняток, функція, список), `assert_called_once_with`, `call_args`, `call_count`, `mock_calls`. Пастка: мок приймає будь-що, тому тест із помилкою в імені методу проходить; `spec=` і `autospec` як захист. Аналог `jest.fn()`.
- [x] `patch`: як декоратор, як контекстний менеджер, через `monkeypatch.setattr`; правило "патчити там, де шукають, а не там, де визначено" (`patch("formbuilder.cli.render")`, а не `patch("formbuilder.render.render")`) з прикладом, де це ламається. Аналог `jest.mock` модуля і чому в Python патчать атрибут, а не модуль.
- [x] `pytest-mock` і фікстура `mocker`: `mocker.patch`, `mocker.spy`, автоматичне зняття після тесту. Чому для pytest це зручніше за `unittest.mock.patch`.
- [x] Мокання часу й випадковості: `patch("module.datetime")` і його пастки, `freezegun`/`time-machine` одним реченням, `random.seed` або інʼєкція генератора.
- [x] Мокання асинхронних функцій: `AsyncMock`, `await` на мок, `assert_awaited_once`. Посилання на m7-l05 для HTTP.
- [x] Альтернатива мокам: fake-об'єкти (реалізація Protocol у пам'яті, посилання на m2-l07), інʼєкція залежностей через параметр, і коли fake кращий за Mock.
- [x] coverage: `pytest --cov=formbuilder --cov-report=term-missing` через `pytest-cov`, читання звіту, `# pragma: no cover`, `fail_under` у конфігу, HTML-звіт. Чому 100% не мета і що означають непокриті гілки (`--cov-branch`).
- [x] Тести, що мовчки нічого не перевіряють: мок без assert, `assert` на мок замість поведінки, перевизначення `side_effect`, яке ніколи не викликається. Як coverage цього не ловить.
- [x] Для капстоуну: тест воркера генерації з fake-рендерером і `AsyncMock` для публікації; тест CLI через `capsys` і `mocker.patch` файлової системи або `tmp_path` замість мока.
- [x] Які JS-звички тут шкодять: `jest.mock("module")` цілими модулями, автоматичні моки, `__mocks__` папки, мокання імпортів ESM (у Python патч атрибута), очікування, що мок без `spec` впаде на неіснуючому методі.
