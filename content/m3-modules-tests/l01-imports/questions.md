# Ключові питання уроку m3-l01 "Система імпортів, __init__.py, циклічні імпорти"

Урок готовий, коли на кожне питання є відповідь з кодом і виводом.

- [x] Що робить `import`: пошук у `sys.modules`, потім по `sys.path`, виконання файлу один раз, кешування модуля як об'єкта. Чому повторний імпорт не виконує код знову і як це відрізняється від ESM (теж один раз) і від CommonJS-кешу. `importlib.reload` одним реченням.
- [x] Форми: `import a`, `import a.b`, `from a import x`, `from a import x as y`, `from a import *` і `__all__`. Чому `from x import *` поза REPL вважають поганим стилем. Відповідності з `import x from`, `import { x }`, `import * as`.
- [x] Модуль проти пакета: файл `.py` проти папки з `__init__.py`; namespace packages без `__init__.py` (одне речення, чому для власного коду `__init__.py` все ж ставлять). Що виконується при імпорті пакета і що кладуть у `__init__.py` (реекспорт публічного API або нічого).
- [x] Абсолютні проти відносних імпортів (`from .config import load`, `from ..core import x`): коли які, чому відносні не працюють у скрипті, запущеному за шляхом (`ImportError: attempted relative import`), і чому курс рекомендує абсолютні.
- [x] `sys.path` і src-layout: чому після `uv sync` пакет імпортується з будь-якої папки (посилання на m0-l06), і що робити з `ModuleNotFoundError` (перевірити `python -c "import sys; print(sys.path)"`, чи активний правильний venv, чи є `__init__.py`).
- [x] Циклічні імпорти: як виникають (A імпортує B, B імпортує A), чому падають з `ImportError: cannot import name` або `partially initialized module`, як діагностувати і як лікувати (перенести спільне в третій модуль, імпорт усередині функції, `TYPE_CHECKING` для імпортів лише для типів).
- [x] Побічні ефекти при імпорті: код верхнього рівня виконується при імпорті, тому `print`, підключення до БД і читання конфігу на рівні модуля це пастка; `if __name__ == "__main__"` (посилання на m0-l03).
- [x] Модуль як singleton і як простір імен для стану: конфіг у модулі, патерн "модуль замість класу-синглтона" (посилання на m4-l08).
- [x] Затінення стандартної бібліотеки власним файлом (`json.py`, `test.py`, `random.py` у корені), як виглядає помилка і як знайти (`module.__file__`).
- [x] Динамічний імпорт: `importlib.import_module("formbuilder.renderers.html")`, навіщо (плагіни, реєстр рендерерів за назвою), `getattr` для об'єкта з модуля. Аналог `await import()`.
- [x] Для капстоуну: розкласти пакет `formbuilder` на `config`, `domain`, `renderers/`, `cli`; показати, які імпорти між ними допустимі (шари зверху вниз) і як `TYPE_CHECKING` розриває цикл між `domain` і `renderers`.
- [x] Які JS-звички тут шкодять: `index.py` як barrel у кожній папці, відносні шляхи `../../`, очікування tree-shaking, default export, імпорт виконується ліниво (у Python одразу).
