# Ключові питання уроку m5-l07 "httpx для асинхронних запитів"

Урок готовий, коли на кожне питання є відповідь з кодом і виводом. Pyodide у платформі має httpx, але без реальної мережі: завдання з `requires: [httpx]` і `runtime: browser` використовують `httpx.MockTransport`; реальні запити лише як `runtime: local`.

- [x] httpx як сучасний клієнт: синхронний і асинхронний API з однаковою формою, `httpx.get` для разових запитів і `httpx.Client`/`AsyncClient` для сесій (пул з'єднань, базовий URL, заголовки). Порівняти з `fetch`: тут є таймаути за замовчуванням, `raise_for_status`, автоматичний JSON. Одне речення про `requests` як попередника.
- [x] Запит і відповідь: `params`, `headers`, `json=`, `data=`, `files=`; `r.status_code`, `r.json()`, `r.text`, `r.headers`, `r.raise_for_status()` і `HTTPStatusError`; `r.request` для дебагу.
- [x] Таймаути і помилки: `timeout=`, `httpx.TimeoutException`, `ConnectError`, ієрархія `HTTPError`; чому "без таймауту" це баг у воркері.
- [x] `AsyncClient` з `async with`, паралельні запити через `gather`/`TaskGroup` з `Semaphore` (посилання на m5-l05), і чому один клієнт на застосунок, а не на запит.
- [x] Ретраї: простий цикл з експоненційною затримкою і `jitter`, які статуси ретраїти (5xx, 429, таймаут) і які ні (4xx), ідемпотентність запиту як умова. Одне речення про `tenacity`.
- [x] Тестування без мережі: `httpx.MockTransport` з функцією-обробником, `respx` або `pytest_httpx` одним реченням; як це дозволяє перевіряти клієнтський код у браузері платформи.
- [x] Стрімінг: `client.stream("GET", url)` і `aiter_bytes` для великих файлів, завантаження статики без читання в пам'ять.
- [x] Автентифікація і заголовки: `auth=(user, pass)`, Bearer через `headers`, власний `httpx.Auth` одним реченням; `event_hooks` для логування запитів.
- [x] Для капстоуну: `Publisher` з `AsyncClient`, що відправляє згенеровану сторінку на вебхук партнера з ретраями, таймаутом і логуванням; тест через `MockTransport`, який імітує 503 потім 200.
- [x] Які JS-звички тут шкодять: `fetch` без таймауту, `await res.json()` (тут `r.json()` синхронний після отримання тіла), перевірка `res.ok` (тут `raise_for_status`), новий клієнт на кожен запит, `axios`-інтерцептори (тут `event_hooks`).
