# Ключові питання уроку m5-l01 "Протокол ітерації: __iter__, __next__, StopIteration"

Урок готовий, коли на кожне питання є відповідь з кодом і виводом. m1-l06 дав `for` на рівні ідеї і посилається сюди за механізмом.

- [x] Iterable проти iterator: iterable має `__iter__`, що повертає iterator; iterator має `__next__` і `__iter__`, що повертає self. `iter()` і `next()` як вбудовані, `StopIteration` як сигнал кінця. Розгорнути `for` у `while True` з `next`. Порівняти з `Symbol.iterator`/`next()`/`{done, value}`.
- [x] Чому ітератор одноразовий і iterable (список) ні: показати `it = iter(lst)`, два проходи; `zip`, `map`, `enumerate`, файл як одноразові ітератори, і пастка повторного використання (порожній другий прохід без помилки).
- [x] Власний ітератор класом: `Countdown` з `__iter__`/`__next__`, стан у екземплярі; чому генератор (m5-l02) майже завжди коротший і цей клас пишуть рідко.
- [x] Розділення контейнера й ітератора: клас-колекція з `__iter__`, що повертає новий ітератор (генератор або `iter(self._items)`), щоб два цикли по одному об'єкту не заважали один одному.
- [x] `next(it, default)` для безпечного взяття першого елемента; `iter(callable, sentinel)` для читання блоками; `StopIteration` усередині генератора стає `RuntimeError` (PEP 479) одним прикладом.
- [x] Ліниве обчислення: ітератор не знає довжини (`len(map(...))` падає), не підтримує індекс, споживає пам'ять по одному елементу; коли це перевага і коли треба `list()`.
- [x] Старий протокол через `__getitem__` з 0..n і чому `str` і власні класи з `__getitem__` ітеруються без `__iter__` (одне речення, посилання на m4-l02).
- [x] `collections.abc.Iterable`/`Iterator` для `isinstance` і типів параметрів (посилання на m2-l07), `reversed` і `__reversed__`.
- [x] Для капстоуну: ітератор обходу дерева елементів у глибину і в ширину як два різні iterable-обгортки над одним конфігом; `next(..., None)` для пошуку першого елемента за умовою.
- [x] Які JS-звички тут шкодять: один об'єкт як iterable і iterator водночас, `{done, value}` замість `StopIteration`, очікування `.length` або індексу на ітераторі, `[...it]` (тут `list(it)`), `for...of` по вичерпаному ітератору в JS теж порожній, але там це рідше трапляється.
