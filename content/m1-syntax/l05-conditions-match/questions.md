# Ключові питання уроку m1-l05 "Умови і match"

Урок готовий, коли на кожне питання є відповідь з кодом і виводом.

- [x] `if / elif / else`: синтаксис, чому `elif`, а не `else if`, вкладеність через відступи. Де звичні фігурні дужки і дужки навколо умови зайві.
- [x] Умова не мусить бути bool: будь-який об'єкт із truthiness (посилання на m1-l03). Ідіоми `if items:`, `if x is not None:`, `if key in d:`. Чому `if x == True:` поганий стиль.
- [x] Тернарний оператор `a if cond else b`: порядок частин, вкладення, читабельність. Чому немає `cond ? a : b`.
- [x] Умовне присвоєння й "walrus" `:=` (3.8+): `if (m := pattern.match(s)):`, `while (chunk := read()):`. Коли це доречно і коли ні.
- [x] Ранній return замість вкладених умов (guard clauses), і чому в Python це читається природно.
- [x] `match` (3.10+): що це не `switch`. Немає fallthrough, немає `break`, порівняння за структурою, а не лише за значенням. Базові кейси: літерали, `|` для кількох, `case _:` як default.
- [x] Структурні патерни: розпакування кортежів і списків `case [x, y]`, `case [first, *rest]`, словників `case {"type": "input", "name": name}`, класів `case Point(x=0)`. Захоплення змінних і чому `case x:` ловить усе (пастка).
- [x] Guard у `case ... if cond:`, патерни з константами через крапку (`case Color.RED`), і чому голе ім'я в `case` це захоплення, а не порівняння з константою.
- [x] Для капстоуну: диспетчеризація елементів форми за `type` через `match` на словнику `{"type": "input", ...}` проти ланцюжка `if/elif` і проти словника функцій `handlers[type]()`. Коли що.
- [x] Як виглядає "switch на словнику" `{"a": fn_a, "b": fn_b}.get(key, default)` і чому це була ідіома до 3.10.
- [x] `pass` у порожній гілці, `assert` як перевірка інваріанту (не для валідації вводу, вимикається `-O`), одне речення про винятки замість кодів помилок із посиланням на m1-l11.
- [x] Які JS-звички тут шкодять: `switch` з `break`, `cond ? a : b`, `if (x = 5)` неможливе в Python без `:=`, `else if`, `===` у порівняннях, очікування, що `case "a":` з рядком це порівняння (так, бо літерал), а `case name:` теж (ні, це захоплення).
