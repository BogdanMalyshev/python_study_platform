# Ключові питання уроку m1-l07 "Функції: аргументи, значення за замовчуванням, *args і **kwargs"

Урок готовий, коли на кожне питання є відповідь з кодом і виводом. Scope, замикання і lambda в m1-l08 і m1-l09; тут лише визначення, виклик і параметри.

- [x] `def`, `return`, функція без `return` повертає `None`, кілька значень через кортеж `return a, b` і розпакування при виклику. Анотації параметрів і результату як норма з першого дня.
- [x] Позиційні та іменовані аргументи: `f(1, 2)`, `f(a=1, b=2)`, змішування, правило "іменовані після позиційних". Чому в Python можна передати будь-який параметр за іменем, і як це замінює об'єкт опцій `{ a, b }` з JS.
- [x] Значення за замовчуванням: обчислюються один раз при `def`, а не при кожному виклику. Пастка mutable default (`def f(items=[])`): показати накопичення між викликами, пояснити механізм через `f.__defaults__`, правильна ідіома `items: list | None = None` + `if items is None: items = []`. Чому в JS `(items = [])` поводиться інакше.
- [x] `*args` і `**kwargs`: збирання довільних позиційних у кортеж і іменованих у словник; розпакування при виклику `f(*lst)`, `f(**dct)`; імена `args`/`kwargs` конвенція. Порівняти з rest/spread і чому `**` не має аналога в JS-параметрах.
- [x] Keyword-only (`*,`) і positional-only (`/`) параметри: `def f(a, /, b, *, c)`. Навіщо `*,` в API (змусити називати булеві прапорці) і де `/` трапляється в stdlib (`len(obj, /)`).
- [x] Порядок у сигнатурі: позиційні, `*args`, keyword-only, `**kwargs`; що станеться при порушенні. Як читати сигнатури в документації і `help()`.
- [x] Передача аргументів: "pass by assignment": усередині функції ім'я прив'язане до того самого об'єкта; мутація списку видна ззовні, переприсвоєння ні. Та сама модель, що в JS з об'єктами, але без винятку для примітивів (бо примітиви незмінні).
- [x] Функція як об'єкт першого класу: передати в іншу функцію, покласти в словник, атрибути `__name__`, `__doc__`, `__defaults__`, `__annotations__`. Детально про замикання й декоратори далі (m1-l08, m5-l04).
- [x] Docstring функції, `help(f)`, стиль однорядкового і багаторядкового docstring (одне речення про Google/NumPy style без деталей).
- [x] Повернення `None` неявно як джерело багів: функція, що мутує і нічого не повертає (`list.sort()` проти `sorted()`), і звичка JS `const x = arr.sort()`.
- [x] Для капстоуну: сигнатура функції-рендерера елемента `render(element, *, theme, depth=0)` з keyword-only параметрами, і чому так зручніше, ніж об'єкт опцій.
- [x] Які JS-звички тут шкодять: об'єкт опцій замість іменованих аргументів, `arguments`, перевантаження через `typeof`, default-параметри з mutable значенням, очікування `undefined` при відсутньому аргументі (у Python `TypeError: missing 1 required positional argument`).
