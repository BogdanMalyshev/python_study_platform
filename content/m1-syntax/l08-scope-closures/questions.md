# Ключові питання уроку m1-l08 "Scope LEGB, global і nonlocal, замикання"

Урок готовий, коли на кожне питання є відповідь з кодом і виводом.

- [x] Правило LEGB: Local, Enclosing, Global, Builtin. Як інтерпретатор шукає ім'я, у якому порядку, і як це показати на прикладі з однаковими іменами на різних рівнях.
- [x] Чому блоки (`if`, `for`, `while`, `try`, `with`) не створюють scope: змінна, визначена всередині `if`, доступна після нього; змінна циклу живе після циклу (коротко, детально в m1-l06). Порівняти з `let`/`const` у блоках JS.
- [x] Хто створює scope: функція, клас (з особливостями, одне речення), модуль, comprehension (3.x, своя область: змінна `x` у `[x for x in ...]` не витікає). Generator expression теж.
- [x] Присвоєння робить ім'я локальним на всю функцію, ще до того, як виконається рядок присвоєння: `UnboundLocalError` при читанні глобальної змінної перед локальним присвоєнням у тій самій функції. Механізм: компіляція функції визначає локальні імена статично.
- [x] `global`: читати глобальну можна без нього, присвоювати ні. Чому `global` майже завжди запах коду і як обходитись (повертати значення, передавати параметр, клас, модуль-стан явно).
- [x] `nonlocal`: для змінних з enclosing-функції. Лічильник через замикання з `nonlocal`, і чому без `nonlocal` `count += 1` падає з `UnboundLocalError`. Чому в JS це просто працює.
- [x] Мутація проти переприсвоєння: `items.append(x)` у вкладеній функції працює без `nonlocal`, бо це не присвоєння імені. Поширений спосіб обійти `nonlocal` через список або словник, і чому це гірше за `nonlocal`.
- [x] Замикання: вкладена функція тримає посилання на змінні enclosing scope. `__closure__`, `cell_contents` як доказ механізму. Фабрики функцій `make_multiplier(n)`.
- [x] Пізнє зв'язування: замикання бачить поточне значення змінної на момент виклику, а не створення. Пастка в циклі `[lambda: i for i in range(3)]` (коротко, повний розбір в m1-l06), виправлення через параметр за замовчуванням і `functools.partial`.
- [x] Builtins: `print`, `len`, `list` це імена з модуля `builtins`, їх можна затінити (`list = [1, 2]` ламає `list()` далі). Як помітити (лінтер, `builtins.list`) і які імена найчастіше затіняють (`id`, `type`, `input`, `str`, `max`).
- [x] `globals()`, `locals()`, `vars()`, `dir()` як інструменти інтроспекції, лише дотик. Чому `locals()` всередині функції це знімок.
- [x] Для капстоуну: контекст рендерингу (тема, глибина, лічильник id) краще передавати параметром або об'єктом, ніж через `global`/`nonlocal`; приклад із генератором унікальних id елементів через замикання.
- [x] Які JS-звички тут шкодять: очікування блокового scope, `var`-подібне мислення про hoisting, присвоєння зовнішній змінній без `nonlocal`, IIFE для ізоляції (не потрібні), модульний патерн через замикання (у Python модуль і так scope).
