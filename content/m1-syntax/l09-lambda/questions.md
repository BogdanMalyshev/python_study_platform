# Ключові питання уроку m1-l09 "lambda, функції вищого порядку і чому в Python пишуть def"

Урок готовий, коли на кожне питання є відповідь з кодом і виводом. Comprehensions детально в m1-l10, тут лише `map`/`filter`/`sorted`/`key`.

- [x] Синтаксис `lambda args: expr`: лише один вираз, без `return`, без інструкцій (`if` як statement, присвоєння, `try` неможливі; тернарний вираз можна). Порівняти з arrow function, яка може мати тіло з блоком.
- [x] Чому lambda не має імені (`<lambda>` у traceback) і чому присвоєння `f = lambda x: x + 1` це антипатерн за PEP 8 (краще `def`). Коли lambda доречна: короткий `key`, callback на один рядок.
- [x] `key=` у `sorted`, `min`, `max`, `list.sort`: lambda, `operator.itemgetter`, `operator.attrgetter`, `str.lower` як key. Стабільність сортування, `reverse=True`, сортування за кількома ключами через кортеж і трюк з `-x` для чисел.
- [x] `map`, `filter` повертають ліниві ітератори, а не списки: `list(map(...))`, одноразовість (ітератор вичерпується). Чому в Python їх зазвичай замінюють comprehension (межа в m1-l10), а `reduce` живе у `functools` і майже не використовується.
- [x] Функції вищого порядку: передати функцію аргументом, повернути функцію, зберігати функції у словнику-диспетчері. Усе, що робили з колбеками в JS, працює так само.
- [x] `functools.partial` як заміна `fn.bind(null, a)` і замиканню для фіксації аргументів; `partial` зберігає `func`, `args`, `keywords`.
- [x] Методи як функції: `str.upper` можна передати як `key` або в `map`, бо незв'язаний метод це функція з `self` першим аргументом. Зв'язаний метод `s.upper` теж об'єкт. Легкий дотик до bound/unbound, детально в m4-l01.
- [x] `operator` модуль: `add`, `mul`, `itemgetter`, `attrgetter`, `methodcaller` замість `lambda x: x[0]`.
- [x] `any`, `all`, `sum`, `max`, `min` з генераторним виразом як ідіоматична заміна ланцюжків `filter(...).map(...)`; `zip` і `enumerate` як функції вищого порядку без колбеків.
- [x] Пастка пізнього зв'язування в lambda (одне речення й посилання на m1-l08), і `lambda i=i:` як виправлення.
- [x] Для капстоуну: реєстр рендерерів `{"input": render_input, "text": render_text}` і вибір за `element["type"]`; сортування елементів форми за `order` через `itemgetter`.
- [x] Які JS-звички тут шкодять: arrow-функції з блоком тіла, ланцюжки `.map().filter().reduce()`, `arr.sort()` без key і з мутацією оригіналу, очікування, що `map` повертає масив, `bind`/`call`/`apply`.
