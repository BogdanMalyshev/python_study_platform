# Нотатки до m6-l04

## Що запускалось

Python 3.12.12 (`.venv/bin/python` з кореня проєкту), mypy 2.4.0, ruff, pydantic 2.14.1, Node v24.9.0.
Тимчасові скрипти лежали в `<scratchpad>/m6-l04/` і видалені після перевірки.

- Усі python-блоки `lesson.md`, за якими йде блок `text`, виконано скриптом, який витягує блоки з файлу
  і порівнює stdout (або stdout плюс останній рядок stderr для прикладів з винятком, або перший рядок
  попередження плюс stdout для `FutureWarning`) з `text`-блоком: 32 блоки збіглися.
  Під час першого прогону два очікувані виводи були неправильні (span у `finditer` і позиція `email`
  у прикладі капстоуну), їх замінено реальним виводом.
- Окремо запущено три блоки з виміряним часом: катастрофічний backtracking `(a+)+$` на n = 20, 22, 24, 25
  плюс атомарна група, посесивний квантифікатор і `a+$`; переривання через `signal.setitimer`; `finditer`
  проти `findall` на тексті 50 МБ. В уроці вивід одного реального прогону на цьому Mac. Блоки не `live`
  і явно позначені як виміряні локально. n = 25 вибрано, бо там близько 1.1 с, а кожна наступна літера
  подвоює час.
- Блок з `reveal_type` перевірено через `mypy --strict typing_demo.py`; в урок вставлено реальний вивід mypy.
- Твердження про Pydantic (`Field(pattern=...)` з Rust-рушієм відхиляє `"email\n"`, з
  `regex_engine="python-re"` пропускає) перевірено запуском і додано в урок окремим блоком.
- Усі 10 `ts`-блоків запущено через `node` як JS (типів у них немає), і коментарі з результатами
  звірено з виводом. Окремо в Node 24 перевірено: `RegExp.escape` існує, модифікатори `(?i:...)`
  працюють, `\w` з прапорцем `u` не ловить кирилицю, `new RegExp(src, "x")` дає `SyntaxError: Invalid flags`,
  `a++` і `(?>a)` дають `SyntaxError`, `matchAll` без `g` дає `TypeError`, `split` з групою зберігає
  роздільники, `(a+)+$` на 25 літерах виконується близько 2.2 с.
- `tasks.yaml` розпарсено через `yaml.safe_load`; для кожного з 5 завдань з кодом `solution + harness` дає
  рівно `expected` після нормалізації, а `starter + harness` не дає. Рішення пройшли `ruff check` і
  `mypy --strict`. Код з кожного з 4 quiz-питань виконано, вивід збігається з варіантом `answer`.
- Перевірено, що кожен id з `tasks.yaml` вставлено в `lesson.md` рівно один раз.

## Рішення

- Розділів теорії 8 плюс `Для капстоуну` і три обов'язкові. Абзаців прози в теорії 40 (верхня межа
  орієнтира) плюс 13 callout-блоків; найдовша серія без коду чи завдання 3 абзаци. Ділити не пропоную:
  `questions.md` має 11 пунктів, і кожен потребує коду. Якщо урок треба скоротити, природна межа: розділи
  "Жадібність, backtracking і продуктивність" та "Коли regex не потрібен" могли б стати окремим коротким
  уроком "регулярні вирази в продакшні".
- У `questions.md` написано, що `\w` у Python Unicode "на відміну від JS без `u`". Насправді в JS `\w` і `\d`
  ASCII навіть з прапорцем `u` (перевірено в Node 24), а літери там шукають через `\p{L}` з `u`. Урок
  подає саме перевірену поведінку.
- Пункт про `$1` у заміні: Python не кидає помилку, а вставляє `$1` буквально; це показано прикладом і
  quiz q4.
- Додано те, чого в `questions.md` немає, але що прямо випливає з тем: атомарні групи й посесивні
  квантифікатори (3.11+) як ліки від backtracking, яких немає в JS; пастка з позиційними прапорцями в
  `re.sub`/`re.split`, які потрапляють у `count`/`maxsplit`; різниця `$` між рушієм Pydantic і `re`.
- Переривання пошуку сигналом показано одним прикладом у callout `Під капотом` з посиланням на m6-l07;
  сигнали тут не пояснюються.
- `html.parser` показано одним прикладом як альтернативу regex для HTML; JSON, CSV, TOML лише з посиланням
  на m6-l02.
- Пакет `regex` згадано одним реченням, як вимагає питання.
- Проєктне завдання p1 у капстоуні (`src/formbuilder/text.py`), бо валідація імен, плейсхолдери і slug
  прямо потрібні бекенду FormBuilder. `verify` за правилом спеки: `cd capstone && uv run pytest tests/test_text.py -q`.
  Сам файл тестів пише учень; запустити `verify` до виконання завдання не можна.
- Транслітерацію кирилиці в slug свідомо не робили, у тексті це сказано.

## Незакриті питання

Немає: усі 11 пунктів `questions.md` закриті кодом з виводом і позначені `[x]`.

## Залежності

- Спирається на m1-l04 (raw-рядки, `SyntaxWarning` для невідомих escape, методи `str`, `str.replace`
  замінює всі), m1-l05 (walrus, звідти вже був приклад з `re.fullmatch`), m2-l06 (generics і narrowing
  для `re.Pattern[str]` / `re.Match[str] | None`), m2-l09 (Pydantic `Field(pattern=...)`), m5-l01
  (лінивий ітератор для `finditer`), m6-l02 (парсери форматів).
- Готує для m6-l05 (subprocess: таймаут через окремий процес як захист від повільного regex, розбір
  виводу рендерера через `finditer`), m6-l07 (сигнали, згадані як грубий таймаут) і капстоуну
  (валідатор імен елементів, лінтер плейсхолдерів, slug для URL опублікованої сторінки).
