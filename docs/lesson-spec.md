# Специфікація уроку

Цей документ отримує кожен агент, який пише урок. Платформа читає файли уроку автоматично, тому формат обов'язковий.

## 1. Файли уроку

Урок живе в `content/<module>/<lesson>/`, наприклад `content/m1-syntax/l06-loops/`. У папці:

| Файл | Хто пише | Що це |
|---|---|---|
| `questions.md` | автор курсу, до агента | Питання, на які урок зобов'язаний відповісти. Не змінювати, лише ставити позначки |
| `lesson.md` | агент | Теорія з розміткою місць для завдань |
| `tasks.yaml` | агент | Завдання з автоперевіркою, тести на розуміння, проєктні завдання |
| `notes.md` | агент | Звіт: що перевірено запуском, які рішення прийняті, що винесено за межі уроку |

## 2. lesson.md

Починається з YAML-frontmatter:

```yaml
---
id: m1-l06
module: m1-syntax
title: "Цикли: for ітерує значення, а не індекси"
summary: "Одне речення: що учень вміє після уроку."
duration_min: 60
prerequisites: [m1-l05]
---
```

Далі Markdown. Правила:

- Заголовки `##` для розділів уроку. Правий сайдбар платформи будується з них, тож 5–8 змістовних розділів теорії (назви не "Вступ" і "Висновки") плюс три обов'язкові закривальні розділи, описані нижче.
- Теорія йде блоками. Після кожної нової ідеї стоїть інтерактивна вставка: або завдання з `tasks.yaml`, або живий приклад коду. Довгий текст без практики не допускається: максимум 6 абзаців поспіль без коду або завдання.
- Завдання вставляється рядком `<!-- task: t1 -->` на окремому рядку, де `t1` це `id` з `tasks.yaml`. Кожне завдання з `tasks.yaml` має бути вставлене рівно один раз.
- Живий приклад коду, який учень може редагувати й запускати прямо в уроці, позначається блоком ```` ```python live ````. Звичайний ілюстративний код просто ```` ```python ````. Вивід прикладу подається після коду коментарями `# -> 42` або окремим блоком ```` ```text ````.
- Зіставлення з JS/TS подається парою блоків: спершу ```` ```ts ```` з тим, як це пишуть у TypeScript, одразу під ним ```` ```python ```` з еквівалентом. Після пари один абзац про те, де поведінка розходиться.
- Callout-блоки це blockquote з жирним маркером на початку. Дозволені маркери:
  - `> **JS-аналог.**` коротке зіставлення без пари кодових блоків
  - `> **Пастка.**` місце, де інтуїція JS-розробника підводить
  - `> **Під капотом.**` механізм, що пояснює поведінку
  - `> **Для капстоуну.**` як це знадобиться в бекенді FormBuilder
- Обов'язкові розділи наприкінці, саме з такими назвами:
  - `## Типові помилки JS-розробника` список з 4–8 пунктів: що пишуть за звичкою, що насправді відбувається, як правильно. Кожен пункт з кодом.
  - `## Підсумок` 5–10 коротких тверджень, які учень має запам'ятати. Без води.
  - `## Що далі` 2–3 речення: який урок наступний і що з цього уроку там знадобиться.
- Розділ `## Для капстоуну` потрібен, якщо тема дотична до бекенду FormBuilder; якщо ні, його немає.

## 3. tasks.yaml

Список завдань. Три типи.

### Завдання з кодом (`type: code`)

```yaml
- id: t1
  type: code
  title: "Коротка назва"
  prompt: |
    Умова в Markdown. Що написати, що повернути. Приклад виклику й результату.
  starter: |
    def chunk(items: list, size: int) -> list[list]:
        ...
  harness: |
    print(chunk([1, 2, 3, 4, 5], 2))
    print(chunk([], 3))
  expected: |
    [[1, 2], [3, 4], [5]]
    []
  hints:
    - "Перша підказка: напрям думки без коду."
    - "Друга: конкретніше, можна фрагмент коду."
  solution: |
    def chunk(items: list, size: int) -> list[list]:
        return [items[i:i + size] for i in range(0, len(items), size)]
  requires: []
  runtime: browser
```

- `harness` дописується після коду учня і друкує результати. `expected` це точний stdout після запуску `starter`-коду учня разом з `harness`. Платформа порівнює після нормалізації: кінцеві пробіли в рядках і порожні рядки на кінці ігноруються, усе інше збігається точно.
- Замість `expected` можна дати `asserts`: блок Python з `assert`, який виконується після коду учня в тому самому просторі імен. Використовувати, коли результат не має єдиного текстового представлення (порядок у множині, float, винятки). Повідомлення в `assert` обов'язкові, їх побачить учень.
- Завдання перевіряє функцію, а не скрипт: учень пише `def`, харнес викликає. Виняток: уроки про синтаксис верхнього рівня, де скрипт доречний.
- 3–6 завдань з кодом на урок. Складність зростає. Перше завдання робиться за 2–3 хвилини, останнє потребує поєднати все з уроку.
- `hints`: 2–3 підказки. Перша без коду, остання майже рішення.
- `requires`: пакети поза стандартною бібліотекою, наприклад `[pydantic]`. У браузері доступні стандартна бібліотека, pydantic і httpx (лише з MockTransport, мережі немає). Усе інше означає `runtime: local`.
- `expected` не може містити виміряний час, адреси об'єктів у пам'яті, шляхи до файлів чи будь-що, що змінюється між запусками. Порядок виводу в asyncio-завданнях гарантується різними тривалостями `sleep`, і це пояснюється в умові.
- `runtime: browser` виконується на платформі через Pyodide, це справжній CPython 3.12 у браузері. Код має бути детермінованим: без реального часу, мережі, файлів поза `tmp`, випадковості без seed. `asyncio` у браузері працює; писати стандартно через `asyncio.run(main())`, платформа адаптує. Паузи через `asyncio.sleep` тримати сумарно до 2 секунд. `runtime: local` для того, що в браузері не запустити: FastAPI, subprocess, реальні файли, потоки. Таке завдання містить `verify` з командою за правилами з розділу "Проєктне завдання" нижче (файли в `practice/<id уроку>/`, запуск з кореня курсу).

### Тест на розуміння (`type: quiz`)

```yaml
- id: q1
  type: quiz
  question: |
    Що надрукує цей код?
    ```python
    for i in range(3):
        pass
    print(i)
    ```
  options: ["2", "3", "NameError", "None"]
  answer: 0
  explain: |
    Цикл не створює scope: змінна `i` живе далі й зберігає останнє значення.
```

- 2–4 тести на урок. Варіанти правдоподібні, неправильні відображають реальні хибні інтуїції JS-розробника. `explain` пояснює не лише правильну, а й чому спокусливі неправильні невірні.

### Проєктне завдання (`type: project`)

```yaml
- id: p1
  type: project
  title: "Валідатор конфігу FormBuilder"
  prompt: |
    Що зробити в репозиторії капстоуну.
  checklist:
    - "Критерій готовності 1"
    - "Критерій готовності 2"
  verify: ".venv/bin/pytest tests/test_config.py -q"
```

Лише для уроків, дотичних до капстоуну, або для `runtime: local`.

Учень запускає `verify` з кореня курсу: копіює команду в термінал, відкритий у корені. Тому кожна команда пишеться від кореня, і варіантів рівно три.

1. **Капстоун.** Репозиторій капстоуну створюється в уроці m0-l06 (`capstone/` у корені курсу, пакет `formbuilder`, src-layout, uv). Завдання виконуються в `capstone/`, а `verify` починається з `cd capstone && uv run ...` (або `cd capstone && uv sync && uv run ...`), наприклад `cd capstone && uv run pytest tests/test_config.py -q`. Шлях до інтерпретатора не пишеться: оточення капстоуну дає `uv run`.
2. **Некапстоунні локальні завдання** (`type: project` і `type: code` з `runtime: local`). Файли учня живуть у `practice/<id уроку>/` у корені курсу, наприклад `practice/m5-l08/event_counter.py`. `verify` виконується з кореня курсу без `cd`, через `.venv/bin/python` або `.venv/bin/pytest` курсу і шляхи від кореня: `.venv/bin/pytest practice/m6-l05/test_run_tool.py -q`, `.venv/bin/python practice/m0-l05/discount.py`. Щоб імпортувати модуль учня, `PYTHONPATH=practice/m5-l08 .venv/bin/python -c "..."`; якщо програма учня шукає файли поруч із собою, перевірка запускає її через `subprocess` з `cwd="practice/<id уроку>"`. Не допускаються `cd practice/...`, `../../.venv`, `~/...` і робочі папки поза `practice/` (`playground/`, `debug-lab/`, `~/python-sandbox` тощо).
3. **uv-завдання модуля 0.** Якщо предмет завдання сам uv і проєкту потрібне власне оточення (свій `pyproject.toml`, `.python-version`, `uv.lock`, `.venv`), проєкт живе в `practice/<id уроку>/<проєкт>/` (або прямо в `practice/<id уроку>/`, якщо проєкт в уроці один), а `verify` має вигляд `cd practice/<id уроку>/<проєкт> && uv run ...` (`uv sync --locked && uv run ...`). Це єдиний виняток з правила "без `cd`" для некапстоунних завдань. Пізніший урок модуля 0 може продовжувати такий проєкт у його папці: m0-l04 p2 дописує конфіг ruff у `practice/m0-l02/formbuilder-draft/`.

Умова завдання називає папку і, якщо `verify` робить щось неочевидне (`PYTHONPATH`, `cd` в uv-проєкт), одним реченням пояснює чому. Агент перевіряє кожен `verify` у scratch-копії кореня курсу (симлінк на `.venv`, файли в `practice/<id уроку>/` або `capstone/`): з еталонним рішенням команда завершується з кодом 0, зі стартовим кодом або на порожній папці з ненульовим.

## 4. Планка якості

- **Повнота.** Урок відповідає на кожне питання з `questions.md`. Наприкінці роботи агент проходить список і ставить `[x]` навпроти закритих. Незакрите питання означає, що урок не готовий. Якщо питання за змістом належить іншому уроку, агент пише це в `notes.md` з обґрунтуванням, але не викреслює мовчки.
- **Обсяг.** Задається повнотою, а не кількістю абзаців. Орієнтир: 20–40 абзаців теорії плюс код. Менше 15 означає тему не розкрито. Більше 50 означає, що це дві теми: написати в `notes.md` пропозицію поділу, урок все одно здати цілим.
- **Механізм, а не рецепт.** Після кожного "як" іде "чому". Для `for` це протокол ітерації, для `is` це identity об'єктів, для mutable default це момент обчислення значень за замовчуванням.
- **Кожне твердження з кодом.** Абзац, у якому стверджується поведінка, супроводжується кодом, що її демонструє, і реальним виводом.
- **Усе перевірено запуском.** Кожен приклад з `lesson.md`, кожне `solution` разом з `harness` агент запускає через `.venv/bin/python` у корені проєкту (Python 3.12, встановлено pydantic, pytest, httpx, pyyaml, ruff, mypy) і вставляє в урок саме той вивід, що отримав. Вигаданого виводу бути не може. У `notes.md` список того, що запускалось. Тимчасові скрипти агент тримає у власній підпапці тимчасової директорії, названій за id уроку (наприклад `<scratchpad>/m1-l04/`), і прибирає лише її: тимчасова директорія спільна для кількох агентів одночасно.
- **Пастки на видноті.** Крайові випадки не між рядків, а окремими callout-блоками `**Пастка.**`.
- **Без дублювання.** Перед написанням агент читає `docs/roadmap.md` і знає, що в сусідніх уроках. Якщо тема сусіднього уроку потрібна тут, дається одне речення й посилання "детально в уроці ...", а не повторний виклад.
- **Актуальність.** Python 3.12. Синтаксис `list[str]`, а не `List[str]`; `match` там, де доречно; `TaskGroup`, а не лише `gather`; Pydantic v2, а не v1.
- **Мова.** Українська. Терміни, для яких усталеного українського відповідника немає, лишаються англійською: scope, truthiness, iterable, event loop, decorator. Код, ідентифікатори, повідомлення помилок англійською.
- **Терміни.** При першій появі в уроці кожного терміна, який учень може не знати з JS-світу (корутина, awaitable, дескриптор, dunder, comprehension, iterable, truthiness, EAFP), дати його англійською в дужках і одним реченням сказати, чи це офіційна назва з документації Python, чи жаргон спільноти. Учень готується до співбесід і має знати, які слова там доречні.
- **Тон.** Два senior-інженери розмовляють. Без вступів про важливість теми, без "давайте розглянемо", без емодзі, без окличних знаків.

## 5. notes.md

Короткий звіт агента:

- Що запускалось для перевірки і чим (команди, версії).
- Рішення, які варто знати автору курсу: що винесено за межі уроку й чому, де обсяг виходить за орієнтир, пропозиції поділу.
- Питання з `questions.md`, які не вдалося закрити, з причиною.
- Залежності від сусідніх уроків: на що урок спирається і що готує для наступних.
