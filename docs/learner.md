# Профіль учня

Один учень, курс пишеться особисто для нього.

- Senior / Lead Frontend Developer, 5+ років комерційної розробки.
- Щоденний стек: JavaScript (ES6+), TypeScript у strict-режимі, React, Next.js, Node.js на рівні SSR, API routes, скриптів і тулінгу.
- Добре знає: асинхронність у JS (Promise, async/await, event loop, мікро- й макрозадачі), модулі ESM, класи й замикання, типи TS (generics, union, utility types, structural typing), Zod для валідації схем, Jest і Cypress для тестів, ESLint і Prettier, npm/yarn, git, Docker на рівні "запустити compose".
- Має lead-досвід: code review, архітектура фронтенду, проєктування JSON-контрактів із бекендом.
- Робочий контекст: будував FormBuilder, конструктор форм і лендингів. Його бекенд був на Python і писали його інші люди; він проєктував контракти й JSON-конфіги. Капстоун курсу: написати цей бекенд самому на FastAPI.
- Python не писав. Читати простий Python може, бо синтаксис очевидний для досвідченого програміста.
- Мова навчання: українська. Терміни й ідентифікатори в коді англійською.

Що з цього випливає для уроку:
- Не пояснювати, що таке змінна, цикл, функція, клас, проміс, тест. Пояснювати, чим Python тут відрізняється і чому.
- Кожну концепцію давати через зіставлення з JS/TS: "у TS ви писали так, у Python це виглядає так, а різниця в поведінці ось де".
- Пастки шукати саме там, де інтуїція JS-розробника підводить: truthiness, `is` проти `==`, mutable default arguments, пізнє зв'язування в замиканнях, `for` без індексу, винятки як control flow, відсутність блокового scope, явний event loop в asyncio.
- Тон: розмова двох senior-інженерів. Без мотиваційних вступів, без "у цьому уроці ми дізнаємось". Коротко, точно, з кодом.
